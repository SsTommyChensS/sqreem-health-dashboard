# Health Insight Dashboard

A responsive web app that turns a fictional user's health & wellness data into a clear, actionable dashboard, with a floating AI assistant that answers questions grounded in that same data.

## Overview

The app presents a persona's health data (steps, sleep, nutrition, goals, recent activity) as an at-a-glance dashboard, then lets the user ask a floating AI assistant follow-up questions like *"How am I progressing?"* or *"What should I focus on?"* — with answers generated by Gemini 3.1 Flash Lite, using only the data shown in the dashboard as context.

## Tech Stack

- **React + TypeScript + Vite**
- **Redux Toolkit** for state management
- **Tailwind CSS** for styling
- **Recharts** for charts
- **Vercel Serverless Function** as a backend proxy to the LLM
- **Google Gemini (gemini-3.1-flash-lite)** for the AI assistant
- **Zod** for LLM response validation

## Getting Started

### Prerequisites
- Node.js 18+
- A Google AI Studio API key (get one at [aistudio.google.com](https://aistudio.google.com/apikey))

### Installation

```bash
git clone <your-repo-url>
cd health-dashboard
npm install
```

### Local Development

1. Copy the environment template and fill in your key:
   ```bash
   cp .env.example .env
   ```
2. Run the dev server:
   ```bash
   npm run dev
   ```
3. Open `http://localhost:5173`.

> The AI assistant calls a serverless function at `/api/chat`. If you're running with Vite alone, use `vercel dev` instead of `npm run dev` so the `/api` route is served locally:
> ```bash
> npm i -g vercel
> vercel dev
> ```

## Environment Variables

Documented in [`.env`](./.env). Never commit a real `.env` file.

| Variable | Required | Description |
|---|---|---|
| `GEMINI_API_KEY` | Yes | Server-side only — used inside `api/chat.ts`, never exposed to the client. |
| `NODE_ENV` | Yes | Environment mode, e.g. `development` or `production` |

On Vercel, set these under **Project Settings → Environment Variables** — do not put them in any `VITE_*` variable, since anything prefixed `VITE_` is bundled into the client and publicly visible.

## Architecture

- The frontend never talks to the LLM provider directly — every AI request goes through `POST /api/chat`, a Vercel serverless function that holds the API key server-side.
- Health data lives in a Redux store (`dashboardSlice`) and is loaded once on app start (simulated async load to exercise loading/error/empty states).
- The chat UI (`chatSlice`) keeps its own conversation history client-side and sends it with each request so the assistant has multi-turn context.

## Product Decisions

- **Summary cards first**: today's steps, sleep, calories, and heart rate are shown before anything else, since that's the "at a glance" answer to *"how am I doing right now."*
- **Trends are separated from goals**: trend charts show raw movement over time; goals show progress against a target — mixing the two would blur "what happened" with "what I'm aiming for."
- **Recommendations are rule-based, not AI-generated**: simple threshold rules (e.g. low sleep → suggest earlier bedtime) run instantly and deterministically, so the dashboard always has something useful to say even before the user opens the AI assistant, which is reserved for open-ended questions.
- **AI assistant is additive, not a replacement for the dashboard**: it's a floating, dismissible panel — the dashboard must be fully useful on its own.

## LLM & Prompt Approach

- **Provider:** Google Gemini (`gemini-3.1-flash-lite`) via `@google/genai` SDK
- The model only ever sees a **structured summary** of the health data (today's snapshot, 7-day averages, goal progress, recent activities) — not the raw dataset — built fresh on every request by `promptBuilder.ts`.
- The system prompt explicitly instructs the model to answer only from the provided `<health_data>` block and to say so, rather than guess, when something isn't covered.
- Responses are requested in a fixed JSON shape (`answer`, `highlightedMetrics`, `confidence`) and validated with **Zod** before rendering — malformed output is caught and handled gracefully.
- Conversation history (last ~10 messages) is sent with every request so follow-up questions keep context.
- Malformed LLM output, timeouts, and provider errors all fall back to a friendly in-chat message instead of breaking the UI.
- Temperature is set to `0.2` and max tokens to `800` to keep responses focused and grounded.

## Known Limitations / Next Steps

- Health data is currently mocked (`src/data/mockPersona.ts`); swapping in real assessment data only requires updating that file, since the types are already defined in `SYSTEM_DESIGN.md`.
- No automated tests yet — given more time, unit tests for the recommendation rules and prompt builder would be the priority.
- No persistence: chat history and data reset on page reload.
